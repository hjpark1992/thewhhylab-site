# AX 레퍼런스 작업 가이드

## 페이지 구조

- 기존 `references/index.html`은 대표 레퍼런스 페이지다. AX 목록은 `references/ax/index.html`, 사례 상세는 `references/ax/<사례명>/index.html`에 둔다.
- 홈페이지는 정적 HTML 구조다. 헤더의 전체 메뉴와 푸터는 페이지마다 HTML에 들어 있다. 새 AX 페이지 5개에도 현재 사이트의 전체 메뉴와 푸터를 각각 넣는다.
- AX 사례 원고는 `references/ax/ax-cases-data.js`에서 관리한다. 목록 카드와 상세 본문은 이 데이터를 사용하므로 사례를 수정할 때 두 화면을 함께 확인한다.

## 자료의 역할

- `더와이랩_AX레퍼런스_담당자전달_20261125_로컬수정반영.zip`: AX 목록, 상세 4개, 전용 CSS·JS·이미지의 최종 전달본. 홈페이지 전체 소스가 아니다.
- `더와이랩_AX_레퍼런스_공유용_20261124.html`: AX 본문 화면을 비교하는 검토용 파일. 상단 안내, 인쇄 버튼, 4개 상세를 한 문서에 이어 붙인 구성은 홈페이지에 올리지 않는다.
- 사이트 공통 메뉴·푸터·경로는 현재 `thewhhylab-site` 저장소의 HTML을 기준으로 한다. 전달본 안의 메뉴가 현재 사이트와 다르면 현재 사이트 메뉴를 유지하고 AX 링크만 추가한다.

## 변경 범위

1. `references/ax/`에 AX 목록 1개, 상세 4개, 필요한 전용 CSS·JS·이미지만 추가한다.
2. 기존 `index.html`과 `references/index.html`의 Library 메뉴에는 AX 레퍼런스 링크 한 개만 추가한다. 기존 본문과 다른 메뉴 항목은 바꾸지 않는다.
3. 상세 페이지의 메뉴·푸터를 JavaScript로 주입하지 않는다. 각 HTML에 현재 사이트의 메뉴·푸터를 넣는다.
4. 검토용 HTML, ZIP 안내 MD, 미사용 스크립트, 이전 로컬 시안은 서버에 올리지 않는다.

## 검증·배포

- 390px·1280px에서 목록과 상세 4개를 모두 열어 제목·카드·캐릭터·표·줄바꿈·푸터를 확인한다.
- 목록의 카드 4개와 상세 링크, 각 상세의 6개 섹션·목록·맨 위·이전/다음 링크를 확인한다. 이미지 누락, JavaScript 오류, 가로 넘침, 깨진 내부 경로가 없어야 한다.
- GitHub Actions의 `deploy.yml`이 `main` 병합 후 Cafe24 FTP로 배포한다. FTP 비밀번호를 채팅이나 저장소 파일로 전달받지 않는다.
- `index.html`과 기존 메뉴 파일의 변경은 코드 소유자 검토 대상이다. `Review required` 상태에서는 병합하거나 FTP로 우회하지 않는다.
- 배포 후 다섯 운영 URL을 다시 열어 200 응답과 실제 화면을 확인한다.

## 이번 작업에서 드러난 문제

기존 시안은 전달 ZIP의 사례 원고를 일반 프로그램 템플릿 카드에 다시 배치해, 공유용 화면의 히어로·파란 카드·캐릭터 배치가 달라졌다. 또 로컬 시안과 GitHub·운영 배포 상태를 구분하지 않아 작업 완료 여부가 혼동됐다. 이후에는 자료별 역할을 먼저 확정하고, 실제 업로드할 파일과 운영 상태를 분리해 확인한다.
