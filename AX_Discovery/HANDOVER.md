### v43 — 아바타 원본 복원 (누끼 후처리 전면 철회)

**문제**: v42의 누끼 후처리가 캐릭터를 훼손함.
배경색(238,238,240)과 색이 가까운 픽셀을 제거하는 방식이었는데, 캐릭터 내부에도
비슷하게 밝은 영역이 많았음 — **눈 흰자, 안경 렌즈 반사, 하늘색 셔츠, 사원증 끈 하이라이트**.
경계 4px 제한을 걸었어도 머리카락처럼 경계가 복잡한 부위에서는 내부까지 밴드에 포함되어 파먹음.

**조치**: 배경 제거 로직 전부 제거하고 **사용자 제공 원본 픽셀 그대로** 사용.
- `img/kim-manager.png` — 원본에서 정사각 크롭(512×512)만 수행, 색·알파 손실 없음
- `img/kim-manager-full.png` — 원본 그대로(586×1038)
- `.speaker-avatar::after` 하단 페이드 제거(원본 배경 유지 버전에서는 불필요)

**교훈**: 밝은 배경 + 밝은 의상/눈 조합의 캐릭터는 색 기반 누끼가 위험함.
꼭 필요하면 수동 마스킹이나 원본 투명 PNG를 확보할 것. 자동 처리 후에는 반드시 **눈·의상·경계 세 곳**을 확대 검수.



### v42 — 아바타 누끼 재작업 + 스토리 본문 줄바꿈

**① 누끼 흰 테두리 제거**
v41의 rembg 기본(u2net) 결과는 머리카락 사이·경계에 원본 배경색(238,238,240)이 남아 있었음.
모델만 바꿔서는(isnet-general-use, u2net_human_seg, alpha_matting) 해결되지 않아 **후처리 파이프라인**을 직접 구성.

1. 배경색과의 색거리로 `bgish` 마스크 생성 (dist < 30)
2. `scipy.ndimage.label` 로 이미지 바깥과 연결된 영역 = 진짜 배경 → 알파 0
3. 머리카락 사이 **갇힌 배경 구멍**(4000px 미만 섬)도 알파 0 처리
4. `distance_transform_edt` 로 **경계 4px 이내 밴드**를 구하고, 그 안에서만
   - 배경색에 가까울수록 알파를 깎아 흰 테두리 제거
   - 색상 디컨태미네이션 `fg = (rgb - BG×(1-α)) / α` 로 배경색 성분 제거
5. 알파 0.5px 블러로 계단현상 완화

⚠️ 4번의 "경계 4px 이내"가 핵심. 처음엔 전체 이미지에 적용해 **이마의 밝은 하이라이트까지 반투명해져 회색 얼룩**이 생겼음.
결과: 배경색 잔존 픽셀 **477 → 1개**

**산출물**
- `img/kim-manager.png` (512×512, 정사각 크롭) — 랜딩페이지용
- `img/kim-manager-full.png` (586×1038, 전신) — 인스타·블로그·제안서 등 재활용용

**② 스토리 본문 줄바꿈**
`.story-text` 를 한 호흡 단위 6줄로 분리(`<br>`), `line-height: 1.9`.
모바일(≤680px)에서는 화면이 좁아 줄이 잘게 쪼개지므로 `.story-text br { display:none }` 으로 자동 흐름 유지.

**② 사외교육 참가신청서 박스가 모바일에서 비정상적으로 커지던 문제**
- 원인: `.appform-box-info { flex: 1 1 320px }`
- 데스크탑은 `flex-direction: row` 라 320px가 **최소 너비**로 동작하지만, 768px 이하에서 `flex-direction: column` 으로 바뀌면 같은 값이 **높이**로 해석됨 → 정보 블록이 320px 높이로 늘어나고 `justify-content: space-between` 이 남는 공간을 벌려 거대한 여백 발생
- 조치: 모바일에서 `flex: 0 0 auto`, `justify-content: flex-start`, 아이콘 52→44px, 패딩 축소 (enhancements.css 63)
- 결과: 모바일 박스 높이 **약 540px → 219px**

**교훈**: `flex: 1 1 <basis>` 를 쓴 요소는 미디어쿼리에서 `flex-direction` 을 바꿀 때 basis 축도 함께 바뀐다는 점을 반드시 확인할 것. 같은 패턴이 `.contact-box-main { flex: 1 1 340px }` 에도 있으나 이쪽은 `flex-wrap: wrap` 유지(방향 전환 없음)라 문제 없음 — 검증 완료.
